# Threat model

Scope: the production topology of `docker-compose.yml` (contract §19), the trust model of the execution sandbox (contract §10.11, ADR-0024), the Claude authentication and credential transport of [ADR-0036](../adr/0036-claude-subscription-oauth-auth.md) with the MCP runtime check of [ADR-0037](../adr/0037-claude-mcp-runtime-precheck.md), and the data flows of contract §§7-17. Controls are listed in [controls.md](controls.md); the proof of each requirements §15 gate is in [quality-gates.md](quality-gates.md). Open platform limitations are in [known-issues.md](../known-issues.md).

Method: assets → trust boundaries → STRIDE per boundary → residual risks. Re-review this document whenever a service, network, volume, secret, auth mode, Claude CLI version or flag, or tool rule changes. Run the "Image CVE review" in `docs/operations/runbook.md` before each release as well.

## 1. Assets

| # | Asset | Where it lives | Why it matters |
|---|---|---|---|
| A1 | Source code of the managed projects | `PROJECTS_ROOT` (host directory, mounted read-only into the worker only) | Confidentiality and integrity of customer code. The platform must never write to it. |
| A2 | Attempt worktrees, bare mirrors, base snapshots | volume `workspaces` (`.repos/`, `<project>/<task>/a<n>/`) | Each task's work in progress. Must be isolated per task. |
| A3 | Claude homes/transcripts, MCP index caches | volumes `claude-home`, `cbm-cache` (per workspace) | They may contain code excerpts and prompts of other tasks. |
| A4 | Database: users, password hashes, sessions, PATs, tasks, logs, audit | `mssql` (`orchestrator`), volume `mssql-data` | Authentication and the record of who did what. |
| A5 | Secrets: sa / service login passwords, Redis password, `ANTHROPIC_API_KEY` (api_key mode only), egress proxy token, TLS keys | `./secrets/*` → compose `secrets:` (`/run/secrets/*`) | They give access to A1-A4 or to the paid Anthropic account. |
| A6 | Queue state, live task streams | `redis` (volume `redis-data`) | Integrity of scheduling; live output can contain code. |
| A7 | Audit log | `orc.AuditLogs` (append-only for app logins) | Accountability and incident forensics. |
| A8 | The host | Docker engine, host filesystem, `~/.ssh`, Docker socket | Full compromise if reached. |
| A9 | Claude subscription OAuth token (`CLAUDE_CODE_OAUTH_TOKEN`, format `CLAUDE_OAUTH_TOKEN_REGEX`, prefix `sk-ant-oat`), the default credential (`CLAUDE_AUTH_MODE=oauth`) | At rest: `./secrets/claude_oauth_token.txt` → `worker` only (`/run/secrets/claude_oauth_token`). In transit and in use: see §3.1 | Long-lived; it stands for the user's whole subscription and works on that account until it is revoked. Parallel attempts share its rate limits (ADR-0036 "Consequences"). |

## 2. Actors

- **Operator / admin / auditor** (authenticated users, contract §15.1). Operators are trusted with their own tasks only; admins configure projects, agents and tool rules; auditors read.
- **Anonymous network client** reaching `web` (8443/8088 on `WEB_BIND_ADDRESS`, loopback by default).
- **Untrusted execution**: the Claude CLI with its tool children, every codebase-memory-mcp server and the project test command. They interpret repository-controlled content (CLAUDE.md, package scripts, test code, tool configs) and model output, so they are treated as attacker-controlled (contract §10.11 trust model).
- **Repository content** itself (a malicious commit, a hostile CLAUDE.md, symlinks, git hooks/filters/attributes).
- **Anthropic API** (external; reached only through the egress proxy).

## 3. Trust boundaries

```
 browser ──TLS──▶ web (nginx, uid 101) ──frontend──▶ api (uid 1000)
                                                     │ backend (internal)
                                     mssql ◀─────────┼─────────▶ redis
                                                     │
                                         worker (uid 1000, git only; projects:ro)
                                                     │ Unix socket (runner-sock, 0660 root:1000)
                                                     ▼
                                  runner launcher (root, 6 caps, sandbox net)
                                    └─ untrusted children (uid 20000+n, 0 caps, prlimit)
                                                     │ sandbox (internal)
                                                     ▼
                                     egress-proxy (uid 1000) ──egress──▶ api.anthropic.com:443
```

| ID | Boundary | Crossing data | Enforcement point |
|---|---|---|---|
| TB1 | Internet/LAN → `web` | HTTPS requests | nginx TLS, loopback bind by default, HSTS |
| TB2 | `web` → `api` | HTTP API, SSE | session/PAT auth, CSRF, Origin check, RBAC, Zod validation, rate limits |
| TB3 | `api`/`worker` → `mssql`/`redis` | SQL, Redis commands | least-privilege logins, parameterised SQL only, TLS to MSSQL, Redis password |
| TB4 | `worker` → git / source repositories | git argv, repository content | `spawn` argv arrays, `--end-of-options`, hardened git config (empty hooks dir, `GIT_CONFIG_GLOBAL=/dev/null`), `projects` mounted read-only, `resolveWithin`/`realpathWithin` |
| TB5 | `worker` → `runner` (Unix socket) | lease and spawn requests (NDJSON, Zod), the OAuth token as `credentialFd {b64}` | socket mode 0660 root:1000, schema validation, `realpathWithin` on lease paths, env allowlist per kind, `assertSafeArgv`, credentials and `credentialFd` for kind `claude` only and never two credentials (`env_rejected`) |
| TB6 | **runner sandbox**: launcher → untrusted children | process start with uid/gid of the lease | per-lease uid without capabilities, 0700 paths handed to that uid only, prlimit, no secrets, no backend network |
| TB7 | Untrusted children → network | HTTPS to Anthropic | `sandbox` network is internal; only `egress-proxy` routes out, only `CONNECT api.anthropic.com:443` with a token that only `claude` processes receive |
| TB8 | Claude CLI → files and tools | tool calls, extensions loaded at start | `--permission-mode dontAsk`, worktree-scoped allow rules, platform deny rules, hardened argv (`--restricted`, inline `--settings`, ADR-0036 Decision 3), fail-closed `init` validation (§10.6) |
| TB9 | Process output → storage, SSE, logs | stdout/stderr, stream-json | `createStreamMasker`/`maskText` before TaskLogs, Redis stream and logs; `maskObject` for audit JSON |
| TB10 | Containers → host | volumes, capabilities, namespaces | no Docker socket, no `~/.ssh`, no host root, `cap_drop: [ALL]`, `no-new-privileges`, `read_only`, non-root users, resource limits |
| TB11 | Claude CLI → its own tool children (Bash, hooks, the MCP server it starts from `mcp.json`) | the Claude credential (A9 or the API key) through env, fds and process memory | **no uid boundary**: in runner mode all of them run as the lease uid, in local mode as the worker user. Enforced by: fd 3 transport (oauth on POSIX), the CLI dropping `CLAUDE_CODE_OAUTH_TOKEN` from children env (ADR-0036 E1), `mcp.json` `env` `ANTHROPIC_API_KEY: ""` (api_key mode), Yama `ptrace_scope >= 1` (runner refuses to start in production otherwise) |

### 3.1 Claude credential transport (ADR-0036 Decision 4)

The auth mode is chosen explicitly (`CLAUDE_AUTH_MODE`, default `oauth`); it is never inferred from which secret is present, because an API key next to an OAuth token silently wins (ADR-0036 A10). Exactly one credential exists per deployment and per spawn (five layers, see controls.md "Claude authentication and credentials").

| Mode / platform | Path of the value | Where the value is visible afterwards |
|---|---|---|
| oauth, POSIX (production runner mode; local mode on Linux) | `claude_oauth_token.txt` → worker config (`CLAUDE_CODE_OAUTH_TOKEN_FILE`, regex-checked) → `LaunchSpec.credentialFd` → runner socket `spawn` frame `credentialFd {b64}` (≤ 4 KiB decoded, kind `claude` only; local mode skips the socket but applies the same rule) → runner decodes, zeroes the byte buffer → `spawnSupervised` opens a fourth stdio pipe, writes the token and ends it → the CLI reads fd 3 to EOF → CLI memory | Worker memory; runner memory while the frame is handled; Claude CLI memory. Claude's environ holds only `CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR=3`; `/proc/<claude>/fd/3` is empty after the read (D-1). Residual: R13, R14 |
| oauth, win32 (local mode only) | `claude_oauth_token.txt` → worker config → Claude env `CLAUDE_CODE_OAUTH_TOKEN` (`spawnSupervised` refuses `credentialFd` on win32: the FD path does not work there, F1) | Claude's process environment for its whole lifetime. Residual: R11 |
| api_key ("not recommended", any platform) | `anthropic_api_key.txt` → worker config → Claude env `ANTHROPIC_API_KEY`; Claude's `mcp.json` gives the MCP server `ANTHROPIC_API_KEY: ""` (`claudeEnvScrub`) | Claude's environment and the environment of every Bash child. Residual: R12 |
| CLI probe (§10.9) | none: no credential variable, no fd 3, no proxy credentials | none |

The token never appears in argv (R3 stays valid), on disk outside the secret file, in `.meta`, or in a log line (controls.md "Claude authentication and credentials", log redaction row).

## 4. STRIDE

| Threat | Boundary | Scenario | Mitigation (see controls.md) | Residual |
|---|---|---|---|---|
| **S**poofing | TB2 | Stolen session cookie or PAT reused | `__Host-` cookie, HttpOnly, SameSite=Strict, Secure; idle/absolute TTL; SHA-256 stored tokens; revocation on password change/disable; PAT scopes (read-only, no token/user management) | A stolen live cookie works until expiry or logout |
| Spoofing | TB2 | Password guessing | scrypt (N=2^17), per-IP and per-username throttling, lockout, constant-cost dummy verify | Low |
| Spoofing | TB5 | A sandboxed process connects to the runner socket to start processes as another lease | socket `0660 root:1000`; sandbox uids are not in group 1000 | None known |
| Spoofing | TB7 | Untrusted test/MCP process uses the egress proxy | proxy demands `Proxy-Authorization` (407 otherwise); token only in the env of `claude` processes | Bash children of Claude inherit it (ratified, ADR-0024) |
| Spoofing | TB11/TB6 | A tool child of Claude (Bash, hook, MCP) or a test/MCP process started by the worker obtains the Claude credential (A9 or the API key) and calls Anthropic as the user | fd 3 transport on POSIX (Claude's environ carries only the fd name); `credentialFd` and every credential variable accepted for kind `claude` only, by the runner and the local launcher (`env_rejected`); the CLI drops the OAuth variable from its children's env; `claudeEnvScrub` empties the key for Claude's MCP server in api_key mode; the probe gets no credential | win32 oauth (R11), api_key Bash children (R12), fd 3 left open (R13), Yama (R14) |
| Spoofing | TB8/TB5 | An `apiKeyHelper`, a stray `ANTHROPIC_API_KEY` or user settings take over Claude's authentication | explicit `CLAUDE_AUTH_MODE`; single-credential rule in five layers; `--restricted` ignores the user `settings.json`; `validateInit` `auth_source` (`apiKeySource` must be `none` in oauth mode and `ANTHROPIC_API_KEY` in api_key mode) → forced kill | None known |
| **T**ampering | TB4 | Task writes to the real repository | `projects` mounted read-only into the worker only; worktrees are created from a bare mirror; source hash checked by tests | None known |
| Tampering | TB4 | Repository-controlled git hooks, filters, `core.fsmonitor`, attributes execute code in the worker | image-owned empty `core.hooksPath`, `GIT_CONFIG_GLOBAL=/dev/null`, hardened `-c` options (contract §11.3); worker runs only git | Depends on git hardening options staying complete (tests in git-manager isolation suite) |
| Tampering | TB8 | Claude edits outside its worktree (siblings, mirror, `.git`) | worktree-scoped allow rules + deny rules; per-lease uid with 0700 dirs (production) | Real-CLI rule semantics are proven only by the release gate `test:claude-live -- permission-boundary` |
| Tampering | TB8 | Non-bare Claude loads attacker-influenced extensions (user hooks, auto memory, user CLAUDE.md, plugins, skills, agents, slash commands), or attribution and git instructions alter commits | one hardened argv for both auth modes: `--include-hook-events --restricted --setting-sources user --settings <frozen inline JSON>` (`disableAllHooks`, `autoMemoryEnabled:false`, empty `attribution`, `includeGitInstructions:false`); env `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1` and `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`; `validateInit` rules `tool`, `tool_missing`, `extension` (`CLAUDE_REVIEWED_EXTENSIONS` per `<cliVersion>/<platform>/<authMode>`), `memory` and `hook_event` (at any time) → forced kill, `security_violation` | Isolation rests on CLI switches verified per CLI version (R4, R15). Components that cannot be disabled (native plugin hooks without events, bundled skills and agents, the LSP manager with 0 servers, the startup prefetch) are bounded by the egress proxy (ADR-0036 "Consequences") |
| Tampering | TB8/TB6 (local mode) | A pre-created or swapped MCP runtime directory (cross-user `/tmp` squat, symlink, world-writable non-sticky `TMPDIR`) is used by the MCP server that Claude starts | `ensureClaudeMcpRuntime` before every Claude spawn: `lstat` of the runtime dir (directory, not a symlink, owned by the process uid, `mode & 0o077 = 0`) and, on POSIX, of `os.tmpdir()` (directory, not a symlink, owned by root or the process uid, sticky or not other-writable). On failure, `MCP_REQUIRED` or the project's `requireIndex` fails the attempt (`security_violation` for `path_escape`, else `workspace_error`); otherwise Claude runs without `--mcp-config` (ADR-0037) | A swap between the check and Claude's MCP spawn is a theoretical TOCTOU window, bounded by the per-uid 0700 parent; runner mode uses leased, runner-validated paths instead |
| Tampering | TB5 | Both credentials are configured, or a token is filed as an API key, which silently switches billing or overrides OAuth (A10) | single-credential rule in five layers: config (`WorkerConfigSchema`, ConfigError naming only the key), `compose-check` and `generate-secrets` (exactly one non-empty credential file, matching the mode and format), the env builder, the runner's `validateSpawnEnv`, and `validateInit` `auth_source` | None known |
| Tampering | TB2 | CSRF on state-changing endpoints | `X-CSRF-Token` equals session token (timing-safe), Origin must equal `PUBLIC_ORIGIN` | None known |
| Tampering | TB3 | SQL injection | parameterised `mssql` inputs only (lint + review rule), DDL denied to app logins | None known |
| **R**epudiation | TB2/TB9 | A user denies having cancelled/created a task | `AuditLogs` row per state change and auth event with actor, IP, request id; app logins cannot UPDATE/DELETE audit | Audit retention purge is an explicit db-cli action (`maintenance.audit_purged`) |
| **I**nformation disclosure | TB2 | Operator reads/streams another operator's task | resource-level visibility (`findVisible`), 404 for invisible tasks on every endpoint incl. SSE (re-validated every 60 s) | None known |
| Information disclosure | TB9 | Secrets appear in logs, TaskLogs, SSE, Problem Details, audit JSON | SecretRegistry + `SECRET_VALUE_PATTERNS` (linear-time), chunk-safe stream masker, pino redact paths, 5xx details never exposed | Secrets in shapes no pattern knows and not registered (e.g. a third-party token in a repository file) are not masked |
| Information disclosure | TB9 | The OAuth token or the base64 `credentialFd` payload ends up in logs, TaskLogs, SSE or runner frames | `@orc/logger` (`maskSecretText`) censors `sk-ant-oat…` values and their base64 and base64url encodings at byte offsets 0, 1 and 2 (also in error messages and stacks, and without a registry, as in the runner), keys `CLAUDE_CODE_OAUTH_TOKEN*` at any depth and `credentialFd`; the runner takes `credentialFd` out of the request before it is processed further; claude-runner registers the token with the SecretRegistry | A partial base64 fragment that starts after the encoded `sk-ant-oat` prefix (a cut-off piece of the token's encoding) matches no pattern (same class as R6) |
| Information disclosure | TB11 | A same-uid tool child reads the token from Claude's `/proc/<pid>/environ` or memory (`/proc/<pid>/mem`, ptrace) | fd path: the environ carries only the fd name; Yama `ptrace_scope >= 1` blocks memory access by processes that are not ancestors (runner: start refused in production when the value is missing, unparsable or 0, warning in development/test; local mode on Linux: one worker warning) | R11 (win32 env), R14 (Yama comes from the host) |
| Information disclosure | TB6 (win32 local) | Claude reads or writes the operator's real `%APPDATA%` / `%LOCALAPPDATA%` (configuration and caches of other tools) | B-020: Claude and the probe get `APPDATA` / `LOCALAPPDATA` below the per-workspace `HOME` (created by the worker) | Test and MCP spawns still get the real values (KI-002); local mode only (R5) |
| Information disclosure | TB6 | Untrusted code reads `/run/secrets`, other worktrees, transcripts or indexes | runner has no compose secrets (the OAuth token passes through in memory only); lease paths owned by the lease uid with 0700; parents 0711 (cbm-cache `{p,w}` parents `root:<WORKER_GID>` 1775: listable, not writable, ADR-0034) | Command lines of other leases are visible in `/proc` (argv carries no secrets) |
| Information disclosure | TB7 | Exfiltration of code to arbitrary hosts | internal networks; proxy allowlist `api.anthropic.com:443`, private IPs denied | Exfiltration to the Anthropic API itself (by design the model sees the code) |
| Information disclosure | TB4 | Path traversal (`../`, absolute, NUL, symlink/junction) in repoPath, JUnit path, CLAUDE.md, workspace removal, API params | `resolveWithin`/`realpathWithin`, `normalizeRepoRelativePath`, `normalizeWorktreeRelativePath`, GUID-only route ids, `parseWorktreeRelPath` | None known |
| **D**enial of service | TB2 | Huge prompts, request floods | JSON body limit, `TASK_PROMPT_MAX_CHARS`, `TASK_TEXT_MAX_BYTES`, rate-limit classes, login throttling | Distributed floods need an upstream proxy |
| Denial of service | TB9 | Pathological output (one 64 KiB+ line without separators) stalls masking | `maskText` and the stream masker are linear-time (regression test: 1 MiB line < 1 s) | None known |
| Denial of service | TB8 | A Claude CLI update (the host CLI in local mode, an image bump in production) changes the init set, and every task stops | intended fail-closed: an unknown `<cliVersion>/<platform>/<authMode>` is an `extension` violation that names the key; release gate `test:claude-live -- probe-init`; upgrade note in `docs/operations/upgrade-rollback.md` | R15 |
| Denial of service | TB7 | An expired or revoked token makes every attempt fail and re-queue (retry storm) | an auth failure ends the attempt once, with no automatic re-enqueue (ADR-0036 Decision 10); token renewal step in `docs/operations/runbook.md` | A dedicated outcome for 401, "Not logged in" and quota exhaustion is deferred to B-022 |
| Denial of service | TB6 | Fork bomb, disk fill, memory exhaustion by untrusted code | prlimit nproc/nofile/fsize/core, runner `pids_limit` 8192 and `mem_limit`, workspace quotas, output limit 50 MiB | OOM restart of the runner interrupts all running attempts (`worker_lost` recovery) |
| **E**levation of privilege | TB10 | Container escape via Docker socket, host mounts, capabilities | no socket, no host root/`.ssh`, `cap_drop: [ALL]`, `no-new-privileges`, `read_only`, non-root users | The runner launcher runs as root (see §5) |
| Elevation of privilege | TB8 | Prompt injection makes Claude run shell commands | `Bash` only with admin-enabled `Bash(<cmd>:*)` rules from a fixed vocabulary; deny list (`curl`, `ssh`, `git push`, ...); hostile text fenced in nonce DATA blocks, `<<<ORC:` removed | Agents with Bash rules execute repository scripts by design (still inside the sandbox) |
| Elevation of privilege | TB4/TB5 | Command injection via titles, prompts, refs, test commands, tool rules | no shell anywhere (`spawn(cmd, argv, {shell:false})`), validators (`isSafeRefName`, `validateTestCommand`, `validateAgentToolRules`, `assertSafeArgv`), prompt via stdin | None known |
| Elevation of privilege | TB3 | App login abused for DDL or reading other tables | per-service logins with GRANT matrix, no sysadmin/db_owner; sa only in `mssql` and `db-bootstrap` | `db-bootstrap` holds sa for its one-shot run |

## 5. Residual risks (accepted)

| ID | Risk | Rationale / compensating controls | Owner |
|---|---|---|---|
| R1 | **Root runner launcher** (`user: "0:0"`, caps SETUID, SETGID, CHOWN, FOWNER, DAC_READ_SEARCH, KILL). Ratified exception, ADR-0024. | Needed to run each lease under its own uid and to hand off/reclaim paths. The launcher executes no untrusted code; it accepts only Zod-validated frames over a 0660 root:1000 socket; children get zero capabilities (`spawn` with uid/gid, libuv drops supplementary groups); `no-new-privileges`, `read_only`, sandbox network only, no compose secrets (it only relays the OAuth token from a `spawn` frame to fd 3, in memory, §3.1), no projects mount. Statically enforced by `tests/security/container-config.test.ts` and `sandbox-escape.test.ts`. | Security + Worker Platform |
| R2 | Bash children of Claude inherit the egress proxy credentials (`HTTPS_PROXY` with the proxy token) in every auth mode, and `ANTHROPIC_API_KEY` in api_key mode (R12). The OAuth token does not reach them on POSIX (fd 3); for win32 see R11. | Only for agents with admin-enabled Bash rules (audited `agent.updated`); no seeded agent has one. | Security |
| R3 | Command lines of other leases visible through `/proc` inside the runner. | argv never carries secrets (prompt on stdin, credentials via fd 3 or env). | Worker Platform |
| R4 | Real-CLI permission semantics and the init set can change with a CLI version. | Release gate `npm run test:claude-live -- permission-boundary` and `-- probe-init`, the frozen init tool list (§10.6) and the reviewed extension table (R15) are re-run on every CLI bump. | QA |
| R5 | `SANDBOX_MODE=local` (development/test, incl. win32) has no OS isolation. Tool children run as the worker user: on Linux they can read the worker's `/proc/<pid>/environ` (Yama does not restrict environ reads), on win32 the environment of any same-user process. A credential handed to the worker as a plain variable (`CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY`) instead of `*_FILE` therefore reaches them through the worker, whatever the transport to Claude. | Refused when `NODE_ENV=production`. The dev scripts default to `CLAUDE_CODE_OAUTH_TOKEN_FILE` (`scripts/lib/dev-env.mjs`); operators use the `*_FILE` form in local mode as well. | Worker Platform |
| R6 | Unknown secret formats in repository content are not masked. | Registry covers all platform secrets; patterns cover common provider tokens. Operators must not store secrets in repositories. | Security |
| R7 | Dependency audit needs registry connectivity (ADR-0027). | Exit 3 "UNAVAILABLE - gate NOT passed" is never treated as a pass; image contents follow the runbook CVE review. | Platform |
| R8 | A stolen session cookie is valid until idle/absolute expiry. | HttpOnly/SameSite/Secure cookie, TLS, 2 h idle / 12 h absolute TTL, logout revokes. | Backend |
| R9 | Stream masker trade-offs: a single pattern match is never split, so an endless token-shaped run is held until it ends; the log sink force-flushes a partial line after `PARTIAL_LINE_MAX_AGE_MS` (2 s), and a private-key block that stays open beyond `maxHoldChars` (64 KiB) is released in pieces. A token suffix that arrives after such a flush, or the body of a > 64 KiB key block, is not recognised by any pattern. | Held text is bounded by the run's total output budget (`countOutput`) and the 2 s flush; real keys are < 4 KiB; registered platform secrets are matched by value regardless of shape. | Security |
| R10 | Untrusted code can enumerate project/workspace GUIDs that have an MCP cache; names are not secrets and grant no access (ADR-0034). | `<CBM_CACHE_DIR>` and `{p,w}` are root-owned 1775 anchors (listable, not writable by sandbox uids); each cache entry is 0700 of its owner uid. | Security + Worker Platform |
| R11 | **win32 oauth (local/dev only).** The token travels in Claude's env (`CLAUDE_CODE_OAUTH_TOKEN`) and stays in its process environment for the whole run. The CLI drops the variable from the env it hands to its Bash, hook and MCP children (E1), but those children run as the same Windows user without isolation and can read Claude's process environment, so the token effectively reaches Claude's Bash children. Same class as api_key mode (R12). | win32 runs only in `SANDBOX_MODE=local`, refused in production (R5). Bash only for agents with admin-enabled rules. The FD path that avoids this works only on POSIX (F1); production is Linux with fd 3. Known issue KI-004. | Security + Worker Platform |
| R12 | **api_key mode: "not recommended".** The CLI does not remove `ANTHROPIC_API_KEY` from its children (E2), and no path is known that keeps it out of Bash children (D-3). Agents with admin-enabled Bash rules can read the key; egress stays limited to `api.anthropic.com:443` and the registered value is masked in output, but the key itself is exposed to repository-controlled code. | Mitigated for MCP: `claudeEnvScrub` gives Claude's MCP server `ANTHROPIC_API_KEY: ""` (proven by D-3). The default mode is oauth; the worker logs one startup warning (`claude_api_key_mode`) in api_key mode; Bash rules stay admin-only and audited. | Security |
| R13 | **fd 3 is drained but not closed.** The CLI reads the token from fd 3 to EOF and keeps the descriptor open. | The writer end is closed right after the write, so the descriptor stays empty (`/proc/<claude>/fd/3` is 0 bytes). Children start after the read and do not inherit fd 3 (D-1b). The runner accepts `credentialFd` only for kind `claude` with `CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR=3`, and never accepts the fd variable without a credential, so no other open descriptor is read as fd 3. A CLI version that reads later or passes fd 3 on is caught by `test:claude-live -- credential-leak` on each CLI bump. | Worker Platform + QA |
| R14 | **Yama `ptrace_scope` comes from the host kernel.** Compose cannot set it (the sysctl is not namespaced). With `0`, a tool child with the same uid (the lease uid in runner mode) can read the token from Claude's memory. | The runner reads `/proc/sys/kernel/yama/ptrace_scope` at start. With `NODE_ENV=production` a missing, unparsable or `0` value refuses the start (the runner never becomes healthy), fail-closed; development and test only warn. Local mode on Linux only warns once (`ptrace_scope_unprotected`) and does not refuse. The runbook describes how to check and persist the setting. | Platform + Worker Platform |
| R15 | **CLI update.** Isolation rests on CLI switches verified per version, so an unreviewed `<cliVersion>/<platform>/<authMode>` stops every task (`extension` violation that names the missing key) until a reviewed `CLAUDE_REVIEWED_EXTENSIONS` entry ships. In local mode an update of the host CLI triggers it. | Accepted availability cost of fail-closed; there is no operator knob by design (K8 8.3). `test:claude-live -- probe-init` re-verifies the table; `docs/operations/upgrade-rollback.md` describes the case. | QA + Worker Platform |
| R16 | **Account exposure.** A leaked OAuth token (A9) works on the user's whole subscription until it is revoked. Parallel attempts share the subscription's rate limits. Sharing one personal token among several users is the operator's responsibility under Anthropic's terms. | Secret mounted into `worker` only, format-checked, never logged (§3.1); renewal and revocation steps in `docs/operations/runbook.md` ("Claude credential (OAuth token)"). | Security + Platform |
